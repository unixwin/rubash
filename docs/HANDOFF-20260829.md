## 3. 族 B — 真实根因（重要：原账本理论作废）

原"输出完整但不退出"不成立。实测（60s 预算，`target/upstream-tests`）：

| 测试 | 实测 | 定性 |
|---|---|---|
| builtins | 4.3s rc=0 | 已自愈 |
| read | 16.2s rc=0 | 慢，超 15s 预算 |
| nquote | 17.6s rc=0 | 慢 |
| arith | 33.5s rc=1 | 慢（rc=1 是否正常待对 GNU） |
| getopts | getopts8 无限循环 | ✅ 已修→DIFF(45/54) |
| printf | 60s+ 卡死 | 双重问题，见下 |

**慢循环根因**：`execute_background_ast_command`（compound_exec.rs:56）
每个后台任务 spawn 真实 rubash.exe `-c <source>`（CreateProcess ~10ms +
完整初始化 + 导出函数序列化进 source）。微基准（2000 次迭代）：
裸循环 1.1s；`echo & wait` 19.5s；`(eval … & )` 11.9s；eval+echo 23.2s。
read.tests 的 read2.sub 正是 2000 次 `(eval "echo {0..$c}" & read -u 9 -t 0.0001)`。
→ 修复方向：后台任务进程内化（线程+状态隔离）或 spawn 减负，大型专项。

**printf 病态基线**：`tests/gnu-compat/upstream-rights/printf.right`
为 2,147,487,629 字节（≈2GiB）。GNU bash 对内联 `%.<digits>s` 精度
不做溢出校验（printf.def 格式扫描器只跳过数字，libc 饱和到 INT_MAX
后真实写出）；`*` 形式才有 getint 校验。卡死点 printf7.sub 的
`printf '%*s' 21474836470` 等：rubash 试图分配/填充天文宽度。
→ 需决策：a) rubash 复刻"饱和到 INT_MAX 真实写出"（对齐 GNU 但
CI 要 diff 两个 2GB 文件）；b) 加入类似 GNU-TIMEOUT.txt 的
"病态基线跳过"清单（现有清单只覆盖 GNU 跑不完，printf 是 GNU 跑完
但产出病态，需新增类别）。

## 4. 族 C（posixexp2）— 探针已完成，修复未动工

**现象**：posixexp2.tests 整文件在 line 16 解析失败
（`syntax error near unexpected end of file`），40 行 GNU 输出 vs 1 行错误。

**最小复现**（探针在 `/tmp/rb-probe/s1.sh`、`r1.sh`；WSL 对照用
`cp <probe> /d/repo/rubash/target/rb-probe/ && MSYS_NO_PATHCONV=1 wsl bash /mnt/d/repo/rubash/target/rb-probe/<x>.sh`）：

| 用例 | GNU | rubash |
|---|---|---|
| `echo ${IFS+'}x'}` | `}x` | `}x}`（多出字面 `}`） |
| `echo ${IFS+'a'bc}` | `abc` | 整行被吞 |
| `echo ${IFS+'}'z}`（未加引号） | `}z` | 状态错乱，波及下一行 |
| `echo "${IFS+'}'z}"`（双引号内） | `'}'z` | `'}'z` ✓ 正确 |
| `echo "$(echo "${IFS+'}'z}")"` | `'}'z` | `syntax error: unexpected EOF while looking for matching ')'` |

**GNU 语义**：未加引号上下文中 `'` 在 `${...}` 内切换单引号模式
（引住的内容字面、引号剥离）；双引号上下文中 `'` 是字面量。

**代码定位**：
- 扫描器 `src/lexer/dolbrace.rs:54 scan_braced_parameter` 能找对闭合；
  `'` 的 toggle 受 `single_quote_has_pair`/`outer_double_quote&&posix`
  启发式控制；产出 `quote_events`。
- **`quote_events` 全库无消费方**（只在 dolbrace.rs 内产生/测试）——
  展开阶段走 `executor/expand_word.rs:45 expand_braced_parameter_word`
  → `expand_braced_operator_or_array_parameter`（+/- 默认词分支在
  `expand_braced_ops.rs`/`expand_braced_special.rs`）用自己的逻辑重新
  处理引号，与扫描器/GNU 不一致。
- 三层嵌套 `$()` 的 EOF 错误在 lexer 的外层命令替换扫描中（尚未定位）。

**下一步**：找到 `+`/`-` 默认词的展开分支，把引号处理对齐 GNU
（未加引号上下文：默认词内 `'..'` 剥引号保内容；双引号上下文：
`'` 字面量）；再修 `$()` 嵌套扫描。修完 posixexp2 应整文件解锁
（族 E 的 braces/comsub-eof 同理检查）。
