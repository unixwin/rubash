# 代码规模（净行数）追踪

本页的数字由 `scripts/code-size.py` 生成、随版本更新；README 顶部的
"net code size" 标签读取同批生成的 `docs/code-size-badge.json`。
计数口径是本项目与 GNU bash 对比的唯一口径，改口径必须同时改脚本、
本页与标签，不得静默漂移。

## 口径摘要

- **净行数（头条）** = 非空行数，且已剔除测试代码与构建生成物。
- Rust（.rs）：跳过 `.git/`、`target/`；满足任一条件的进 tests 桶、不进头条——
  路径组件恰为 `tests`、路径组件以 `_tests` 结尾、文件名为 `tests.rs` 或以
  `_tests.rs` 结尾、文件是 `#[cfg(test)] mod NAME;` 声明的解析目标
  （含 `#[path = "..."]`）。benches/benchmarks/examples 组件进 aux 桶单列。
  主桶文件内 `#[cfg(test)] mod ... { ... }` 块按词法感知的大括号配平整段
  摘除（字符串/原始字符串/字符字面量/注释内的括号不计数）。
  `#[cfg(test)]` 修饰的非 mod 项按口径不摘除，脚本以备忘计数披露。
- C（.c + .h），与上对称。用 `--pristine` 给出发版树时，构建树里相对路径
  不在发版树中的 .c/.h 一律判为构建生成物剔除并列名——GNU 基线即用此法
  把 bash 5.3.20 构建树（= 5.3 发版树 + 官方补丁 1–20）与发版 tarball 对齐，
  剔除的 11 个生成文件为：buildconf.h、builtins/builtext.h、builtins/builtins.c、
  builtins/pipesize.h、config.h、lsignames.h、pathnames.h、signames.h、
  stdckdint.h、syntax.c、version.h。
- 物理行数同时报告作对照；毛数（含测试）不作头条。

## 更新方式

发版时由 `.github/workflows/code-size.yml`（release 发布或手动触发）重跑
脚本并提交本页与标签数据的更新；也可手动：

```sh
python3 scripts/code-size.py --pristine <bash-5.3 发版树> \
  --write-md docs/code-size.md \
  --badge-out docs/code-size-badge.json --badge-vs gnu-5.3.20 \
  "rubash=." "gnu-5.3.20=<bash 5.3.20 源码树>"
```
